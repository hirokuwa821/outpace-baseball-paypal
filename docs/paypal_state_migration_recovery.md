# PayPal 保存先移行：状態別の復旧手順

対象: `paypal_state.py`、`paypal_state_migration.py`。

## 大原則

- **既存ファイルを無条件に削除しない。** 削除は、下表の「削除してよいもの」に当てはまるものだけ、内容を確認してから行う。
- **移行元（`src` フォルダの旧 `subscriptions.db` と `paypal_resource_ids.json`）は決して削除・移動しない。** これが唯一の確実な退避先。
- 作業前に Streamlit と uvicorn を両方止める。
- `OUTPACE_PAYPAL_STATE_DIR` は、Streamlit と uvicorn の両方に同じ値で渡す（アプリは子プロセスへ同じ値を明示的に渡すが、親の値が一致していることが前提）。

## 完了マーカーについて

`migration-complete.json` は、DB とキャッシュが検証済みであることの最後の証拠。

- 形式: `format`、`version`（現在 1）、`completed_at_utc`、`database`、`cache` が必須。
- 書き込みは一時ファイル → fsync → 原子的な置き換え。途中で止まっても最終名は現れない。
- 利用時の確認は構造と存在のみ。DB やキャッシュの内容は見ない（通常運用の更新で壊れないため）。

## 状態別の対応

| 状態 | 起きること | 対応 |
|---|---|---|
| **A. DB とキャッシュのコピーは成功、マーカー作成は失敗** | 移行先に DB とキャッシュがあり、マーカーがない。旧データがある間は利用が拒否される。 | 移行先の DB とキャッシュは**そのまま残す**。移行先の内容を確認したうえで、`write_migration_marker(移行先, report)` を手動で呼ぶ（report は `{"database": ..., "cache": ...}`）。書けない場合は、移行元を使い続ける（環境変数を `src` に向ける）。 |
| **B. マーカーの一時ファイルだけ残っている**（`.migration-complete-*.tmp`） | 最終マーカーは無い。一時ファイルは利用されない。 | 一時ファイルは無視してよい。内容を確認し、不要と判断したら**その一時ファイルだけ**を削除。最終マーカーは、状態 A の手順で作る。 |
| **C. マーカーが壊れている**（空、JSON 不正、形式違い、version 違い、項目欠落） | 利用が拒否される（`MigrationMarkerError`）。 | 壊れたマーカーは削除せず、名前を変えて退避（例: `migration-complete.json.broken`）。状態 A の手順で、検証済みの報告から作り直す。 |
| **D. DB だけ存在する** | マーカーが無く、旧データがあれば利用が拒否される。 | DB は削除しない。内容（行数、テーブル）を確認し、キャッシュのコピーを行う（`copy_cache`）。両方そろったら状態 A の手順でマーカーを作る。不完全と判断したら、移行先 DB を退避してから、移行をやり直す。 |
| **E. キャッシュだけ存在する** | 同上。Plan 作成は拒否される。 | キャッシュは削除しない。DB のコピーを行い（`copy_database`）、マーカーを作る。 |
| **F. マーカーはあるが DB またはキャッシュが無い** | 利用が拒否される（`MigrationMarkerError`）。 | マーカーを削除しない。欠けているファイルの出所（移行元）を確認し、移行をやり直す。移行先に既存ファイルがある場合、`migrate_all` は拒否する（そのまま）ので、先に欠けている側だけを退避してから、実行する。 |

## 移行をやり直す場合

1. 移行先の状態を `plan_migration(target_dir=移行先)` で確認する（書き込みなし）。
2. 移行先に既存の DB、キャッシュ、マーカーのどれかがあれば、**内容を確認してから**、そのファイルだけを退避する（削除しない）。
3. `migrate_all(移行元DB, 移行元キャッシュ, 移行先)` を実行する。
4. 成功したら、環境変数を移行先に設定して起動し、動作を確認する。
5. 旧ファイルは最低でも数回の正常運用が確認できるまで残す。

## 絶対にしないこと

- 移行元の削除・移動・上書き。
- 「移行先のファイルを消せば直る」という前提の削除。
- マーカーを手で空ファイルとして作る（検証を通らない。利用は拒否される）。
- 2 つのプロセスで別々の保存先を指す状態での起動（画面と PayPal サーバーの保存先が一致しないと、購入は拒否される）。
